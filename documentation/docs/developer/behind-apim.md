# Serving behind Azure API Management

The API is deployed to Azure Container Apps and exposed publicly through an
Azure API Management (APIM) instance:

| URL | What it is |
|---|---|
| `https://rcpch-nhs-organisations.greenrock-df7c746b.uksouth.azurecontainerapps.io` | The raw container app URL (no prefix). Used for debugging and health probes. |
| `https://api.rcpch.ac.uk/nhs-organisations/v1` | The public APIM URL. This is what consumers should use. |

The Django app itself is mounted at the URL root (see
`rcpch_nhs_organisations/urls.py`), so on the raw container URL the routes are
`/`, `/schema/`, `/swagger-ui/`, `/organisations/`, etc.

## Why the schema / Swagger UI 404 through APIM

APIM only forwards paths that match an **operation** defined on the APIM API.
The data endpoints (`/integrated_care_boards/`, `/organisations/`, …) worked
because operations existed for them, but `/`, `/schema/`, and `/swagger-ui/`
had no operations — so APIM rejected them with 404 before they reached the
backend.

There is a second, related problem: even once APIM forwards
`/nhs-organisations/v1/swagger-ui/` to the backend, the Swagger UI page embeds
a `specUrl` generated by Django via `reverse("schema")`. Without a prefix
configured, that URL is `https://api.rcpch.ac.uk/schema/` (no
`/nhs-organisations/v1`), so the spec fetch inside the page would 404.

## The fix

The fix is in two places: APIM (add operations, exempt docs from the
subscription key, send a prefix header) and Django (make URL generation
prefix-aware, declare the subscription key in the OpenAPI spec).

### 1. APIM — add the missing operations

Add operations on the APIM API for:

| APIM operation path | `rewrite-uri` template | Purpose |
|---|---|---|
| `/` | `/` | DRF browsable API root |
| `/schema` | `/schema/` | OpenAPI JSON |
| `/swagger-ui` | `/swagger-ui/` | Swagger UI HTML |

`rewrite-uri` forces the trailing slash so Django matches the route first
time without a 301 redirect (which would otherwise need a second operation
for the slashed path).

### 2. APIM — exempt the docs operations from the subscription key

APIM's "Subscription required" setting is API-level, not per-operation, so
there is no toggle to exempt individual operations while keeping it on for
the rest. The workaround:

1. Turn **off** "Subscription required" on the API.
2. Add an API-level inbound policy that requires the
   `Ocp-Apim-Subscription-Key` header for the data endpoints but not for the
   docs paths:

```xml
<inbound>
    <base />
    <set-header name="X-Forwarded-Prefix" exists-action="override">
        <value>/nhs-organisations/v1</value>
    </set-header>
    <choose>
        <when condition="@(
            !context.Request.Url.Path.Equals('/nhs-organisations/v1') &amp;&amp;
            !context.Request.Url.Path.Equals('/nhs-organisations/v1/') &amp;&amp;
            !context.Request.Url.Path.Equals('/nhs-organisations/v1/schema') &amp;&amp;
            !context.Request.Url.Path.Equals('/nhs-organisations/v1/schema/') &amp;&amp;
            !context.Request.Url.Path.StartsWith('/nhs-organisations/v1/swagger-ui')
        )">
            <check-header
                name="Ocp-Apim-Subscription-Key"
                failed-check-http-code="401"
                failed-check-error-message="Subscription key required."
            />
        </when>
    </choose>
</inbound>
```

!!! warning "Subscription key validation"
    With "Subscription required" off, APIM no longer validates the key
    against its subscription database. The `<check-header>` policy above only
    verifies the header is **present**, not that it is a valid key. A client
    sending `Ocp-Apim-Subscription-Key: anything` would pass. This is
    acceptable for read-only endpoints, but if the data endpoints are ever
    made writable, add backend-side auth or use a `<send-request>` policy to
    validate the key against the APIM management API.

### 3. APIM — send `X-Forwarded-Prefix`

The `set-header` in the policy above sets `X-Forwarded-Prefix:
/nhs-organisations/v1` on every forwarded request. This tells Django what to
prepend when generating URLs. Without it, the backend would serve the pages
but every link inside them (the Swagger UI `specUrl`, hyperlinked serializer
URLs, pagination links) would point at the unprefixed path and 404.

`X-Forwarded-Host` is set by APIM by default, and `USE_X_FORWARDED_HOST = True`
is already set in `settings.py`, so `build_absolute_uri()` produces
`https://api.rcpch.ac.uk/...` rather than the container-app host. No change
needed there.

### 4. Django — `ForwardedPrefixMiddleware`

`rcpch_nhs_organisations/middleware.py` defines
`ForwardedPrefixMiddleware`, wired in as the outermost middleware in
`settings.py`. When `X-Forwarded-Prefix` is present it:

1. Strips the prefix from `PATH_INFO` if the proxy forwarded the full
   prefixed path (so the URL resolver still matches the unprefixed routes in
   `urls.py`). This makes the middleware robust to either APIM forwarding
   style — with or without a path rewrite.
2. Sets `SCRIPT_NAME` to the prefix so that `reverse()`,
   `build_absolute_uri()`, hyperlinked serializer URLs, pagination links,
   and the Swagger UI `specUrl` all include the prefix.
3. Restores the previous script prefix afterwards so the prefix does not
   leak out of the request (e.g. into management commands run in the same
   process, or into non-proxied requests).

The prefix is validated against a conservative allow-list of URL path
characters to prevent header injection.

### 5. Django — APIM subscription key in the OpenAPI spec

`rcpch_nhs_organisations/openapi_hooks.py` defines a postprocessing hook
(`add_apim_subscription_key_security`) wired into `SPECTACULAR_SETTINGS` that
injects the APIM subscription key as an OpenAPI security scheme when the
schema is requested through APIM (i.e. `X-Forwarded-Prefix` is present).

This makes Swagger UI show an **Authorize** button. A consumer enters their
APIM subscription key once; Swagger UI then sends
`Ocp-Apim-Subscription-Key` on every "Try it out" request, so the data
endpoints return 200 instead of 401.

The hook is a no-op when the header is absent, so the raw Azure URL and
local dev produce a spec with no security scheme and no lock icons —
reflecting that no key is needed there.

## Will this break development?

No. Both the middleware and the OpenAPI hook are **no-op when
`X-Forwarded-Prefix` is absent**:

- Local dev via Caddy / `./s/dev` — no header, no change.
- Direct access to the container app (the raw Azure URL) — no header, no
  change. `/`, `/schema/`, `/swagger-ui/` continue to work unprefixed, and
  the OpenAPI spec shows no security scheme.
- Health probes — no header, no change.
- `api_comparison.py` against the raw Azure URL — no header, no change.
- Management commands run inside the container — no HTTP request, no
  change.

The prefix and security scheme are only applied when APIM sends the header.
Tests in `rcpch_nhs_organisations/hospitals/tests/test_forwarded_prefix.py`
cover both the prefixed and unprefixed cases, including that neither the
prefix nor the security scheme leaks between requests.

## Security note

`X-Forwarded-Prefix` is a client-controlled header. If a client could reach
the container app directly and send this header, they could make Django
generate URLs with an arbitrary prefix. The middleware validates the prefix
against `^/[A-Za-z0-9._\-/]*$`, which limits the damage to URL generation
(it cannot change routing, since the prefix is only stripped from
`PATH_INFO` when it actually matches). For full hardening, ensure the
container app ingress only accepts traffic from APIM (network isolation /
private endpoint), so untrusted clients cannot inject the header.

## Verifying the fix

After deploying both the APIM config and this code:

```bash
# No key needed — should return the OpenAPI JSON.
# Through APIM it includes a securitySchemes.OcpApimSubscriptionKey entry.
curl https://api.rcpch.ac.uk/nhs-organisations/v1/schema/ | python -m json.tool | grep -A4 OcpApimSubscriptionKey

# No key needed — should return the Swagger UI HTML.
# The embedded specUrl should contain /nhs-organisations/v1/schema/.
curl -s https://api.rcpch.ac.uk/nhs-organisations/v1/swagger-ui/ | grep -o 'url: "[^"]*schema[^"]*"'

# No key needed — should return the DRF browsable API root with prefixed links.
curl https://api.rcpch.ac.uk/nhs-organisations/v1/

# Key required — without a key this returns 401, with a valid key it returns 200.
curl -i https://api.rcpch.ac.uk/nhs-organisations/v1/integrated_care_boards/
```

The raw container URL should continue to serve the same pages unprefixed and
with no security scheme in the spec:

```bash
curl https://rcpch-nhs-organisations.greenrock-df7c746b.uksouth.azurecontainerapps.io/schema/
curl https://rcpch-nhs-organisations.greenrock-df7c746b.uksouth.azurecontainerapps.io/swagger-ui/
```
