How to create it:

{% if change.level == 'organisation' %}
  • Create the missing organisation from the ODS Spine:
    python manage.py mergers --organisations {{ change.payload.target_ods_code }} --create
    This fetches the organisation's name, address, postcode, and parent trust from ODS and creates the row with baseline relationships.
  • Then re-approve this change to record the OrganisationSuccession row and close the predecessor.
  • If you have already recorded the succession manually (e.g. via the admin succession page), dismiss this row with a reason instead.
{% elif change.level == 'trust' %}
  • Open the successor trust's admin page and use the Backfill merger… wizard. It fetches the predecessor from ODS, creates the Trust row (with active=False), writes the version rows (historical name + closure), and creates the TrustSuccession row — all in one transaction.
  • After the wizard completes, dismiss this pending row with a reason (e.g. "Succession recorded via Backfill merger wizard"), since the wizard writes the succession row directly.
  • If the predecessor is a genuinely new trust (not a historical predecessor), apply the matching roster-add change first, then re-approve this one.
{% elif change.level == 'icb' %}
  • Use the Backfill merger… wizard on the successor ICB's admin page, or run python manage.py backfill_successions --entity icb to backfill ICB successions from the ODS Succs block.
  • After the backfill completes, dismiss this pending row with a reason.
{% else %}
  • Apply the matching roster-add change first (if one exists), then re-approve this one.
  • If no roster-add change exists, create the entity manually via the admin, then re-approve.
{% endif %} {% endif %}
