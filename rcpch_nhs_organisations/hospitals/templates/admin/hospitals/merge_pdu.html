Merge {{ object }} with another PDU into a new PDU

PDUs are not tracked by the ODS, so the new PZ code, name, and network are entered manually. This records a forward full merger: this PDU and the other predecessor are both dissolved, and a new successor PDU is created. In one transaction:

  1. Creates the successor PDU with a baseline PaediatricDiabetesUnitVersion row, snapshotted to the chosen network, name source, and lead organisation.
  2. Opens a PaediatricDiabetesUnitNetworkMembership row linking the successor to the chosen network.
  3. Creates two PaediatricDiabetesUnitSuccession rows (type=merger), one per predecessor, both pointing at the successor.
  4. Closes each predecessor's current version row and opens an inactive one. Marks both predecessors active=False.
  5. Reassigns all child organisations of both predecessors to the successor.
  6. Sets the lead_organisation FK on the successor to the chosen lead organisation, so the /paediatric_diabetes_units/{pz_code}/parent/ endpoint reads the lead from the model.
Note: the new PZ code must not already exist. If the successor PDU already exists, use the Acquire another… action instead.
This cannot be undone. Verify the new PZ code, the other predecessor, the network, the name source, the lead organisation, and the effective date before proceeding.
